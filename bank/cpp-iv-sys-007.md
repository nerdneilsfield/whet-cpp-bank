# 内存碎片（Memory Fragmentation）是什么？堆碎片 vs 栈不碎片的原因？

## Explanation

### 什么是内存碎片

**内存碎片**是指进程的地址空间中存在无法被有效利用的间隙，分两类：

**外部碎片（External Fragmentation）**  
空闲内存分散为多个不连续的小块，每块单独足够小，但总量却满足需求。例如：堆上有 3 个 32 KB 的空闲洞，但 `malloc(64KB)` 仍然失败，因为找不到连续的 64 KB。

**内部碎片（Internal Fragmentation）**  
已分配给程序的内存块中有部分字节未被使用。常见原因：分配器有最小粒度（如 16 字节对齐），申请 1 字节却得到 16 字节，多余的 15 字节是内部碎片。

### 为什么堆容易碎片化

堆的生命周期由**运行时决定**，分配和释放顺序完全不规律：

```
时刻 1：malloc(A=64)  malloc(B=128)  malloc(C=64)
堆：[A:64][B:128][C:64]

时刻 2：free(B)      → 中间出现 128 字节空洞
堆：[A:64][    :128    ][C:64]

时刻 3：malloc(200)  → 无法满足！总空闲=128，但不连续（若 A、C 之外还有其他碎片）
```

形成碎片的根本原因：
1. **生命周期交错**：对象 A 存活期间，B 和 C 已经被释放，留下空洞。
2. **大小各异**：小块释放后，其他大小的新分配未必能完美填充。
3. **不可压缩**：C/C++ 堆指针是裸地址，GC 型语言（Java）可移动对象整理碎片；C++ 不行。

### 为什么栈不产生碎片

栈遵循严格的 **LIFO（后进先出）** 规律：

```
调用 foo():   SP ↓ 分配帧
  调用 bar():   SP ↓ 分配帧
  返回 bar():   SP ↑ 回收帧（完全还原）
返回 foo():   SP ↑ 回收帧（完全还原）
```

1. **分配即扩展，回收即收缩**：帧的释放顺序与分配顺序严格相反，不会留下孔洞。
2. **大小编译期已知（多数情况）**：函数局部变量大小在编译期确定，`SP` 只需加减一个常量。
3. **无碎片化状态**：在任意时刻，栈都是一段连续的"已用区 | 未用区"，分界线就是 `SP`，不存在已用中间夹空闲的情况。

注：`alloca`/VLA 引入可变大小分配，但仍受 LIFO 约束，所以不破坏无碎片性。

### 缓解堆碎片的工程手段

| 方案 | 原理 |
|------|------|
| **内存池（Memory Pool）** | 预分配固定大小块，消除外部碎片 |
| **Slab 分配器**（Linux 内核） | 按对象类型预分配，同类对象紧凑排列 |
| **jemalloc / tcmalloc** | 按 size class 分桶，减少碎片并提升多线程性能 |
| **Arena 分配器** | 批量申请大块，业务对象在其中线性分配，整体释放 |
| **对象池 / `std::pmr`**（C++17） | 多态内存资源接口，按场景选用不同分配策略 |
