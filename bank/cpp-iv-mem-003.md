# 栈 vs 堆的分配方式和性能差异？

## 参考答案

### 分配机制

**栈（Stack）**：由 CPU 的栈指针寄存器（`rsp`/`esp`）管理。函数调用时编译器在编译期计算局部变量总大小，进入函数时将栈指针向下移动对应字节即完成分配，返回时向上恢复——本质是一条 `sub rsp, N` 指令，O(1) 且无任何运行时查找。

```cpp
void foo() {
    int a = 1;     // rsp -= 4（概念上）
    int b[100];    // rsp -= 400
}  // ret 时 rsp 恢复
```

**堆（Heap）**：由运行时库（glibc `ptmalloc2`、jemalloc 等）维护空闲链表/分箱结构。每次 `new`/`malloc` 需要：查找合适空闲块 → 分裂块 → 更新元数据 → 返回指针；`delete`/`free` 需合并相邻空闲块（coalescing）。最坏情况 O(log n) 乃至 O(n)，且可能触发 `sbrk`/`mmap` 系统调用。

### 性能对比

| 维度 | 栈 | 堆 |
|------|----|----|
| 分配速度 | 极快（1–2 ns，单条指令） | 较慢（50–100 ns，需查找） |
| 释放速度 | 极快（函数返回时批量） | 较慢（需合并空闲块） |
| 缓存局部性 | 优（数据集中，栈帧连续） | 差（碎片化，跳转多） |
| 最大容量 | 小（默认 1–8 MB） | 大（受虚拟地址空间限制） |
| 生命周期 | 函数作用域内 | 手动控制 |
| 线程安全 | 天然独立（每线程一个栈） | 需要锁（glibc arena 分锁） |
| 碎片 | 无 | 有（外碎片/内碎片） |

### 典型陷阱

```cpp
// 错误：返回栈上局部变量的指针（dangling pointer）
int* bad() {
    int x = 42;
    return &x;   // UB：x 在函数返回后已销毁
}

// 正确：堆上分配，生命周期由调用方管理
int* good() {
    return new int(42);   // 调用方负责 delete
}
// 更好：用智能指针
std::unique_ptr<int> best() {
    return std::make_unique<int>(42);
}
```

### 实践建议

- 小型、生命周期局限于函数内的对象 → 优先栈，缓存友好且零开销。
- 大对象（> 栈默认大小的 10%）、生命周期不确定、需要多态的对象 → 堆。
- C++ 核心指导原则（CppCoreGuidelines）：**不要不必要地堆分配**（R.5）。
