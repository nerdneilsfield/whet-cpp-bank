关于有符号整数溢出，以下说法正确的是哪些？

```cpp
int f(int x) {
    return x + 1 > x;          // (1) 编译器优化？
}

int g(int x) {
    if (x + 100 < x) return -1; // (2) 检测溢出
    return x + 100;
}
```

A. C++ 标准规定有符号整数溢出是 **未定义行为**；无符号溢出则定义良好（模 2^N 环绕）。
B. (1) 中由于"x + 1 > x"在不溢出时恒为 true，且溢出是 UB（编译器可假设不发生），优化器可能直接把整个函数优化为 `return true;`。
C. 使用 `-fwrapv` 选项后，有符号溢出仍是 UB，但编译器承诺生成特定结果。
D. (2) 是常见错误"溢出后检测"，由于溢出本身就是 UB，编译器可假设溢出永不发生，从而 `x + 100 < x` 被优化为恒 false，整个检测被消除。

---

**解析：**

A 正确：标准 [expr]/4 明确有符号溢出是 UB；无符号在 [basic.fundamental]/2 定义为模 `2^N` 环绕，无溢出可言。这是 C/C++ 最常被误解的规则之一。
B 正确：基于 UB 优化是现代编译器（GCC/Clang）的核心机制。编译器假设 UB 不发生，从而推断 `x + 1 > x` 恒成立，整个函数被优化为常量 `true`。即使你期望"溢出时返回 false"也得不到。
C 错误：`-fwrapv` 改变了编译器的语言契约——在该标志下有符号溢出**定义**为环绕，**不再是 UB**，编译器不能再做 "溢出不会发生" 的优化。该选项的目的正是让 UB 变为已定义行为。
D 正确：(2) 是经典的"事后检测溢出"反模式；正确做法应在加法前检测（如 `x > INT_MAX - 100`），或使用 `__builtin_add_overflow`、C++26 的 `<numeric>` checked 算术。

## Explanation

A、B、D 正确：有符号整数溢出是未定义行为，优化器可据此假设溢出不会发生并删除看似合理的检测。无符号整数才有模 2^N 回绕语义。常见误区是在溢出发生后再比较来检测溢出；正确做法是在运算前检查边界或使用专门的 checked arithmetic。
