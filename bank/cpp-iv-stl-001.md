# `std::vector` 的扩容策略？为什么是倍增而非固定增量？

## 问题

`std::vector` 在空间不足时如何扩容？为什么标准实现选择按比例扩容（2 倍或 1.5 倍）而不是每次固定多分配若干元素？

## 参考答案

### 扩容触发与基本流程

当 `push_back` / `emplace_back` 导致 `size == capacity` 时，`vector` 触发扩容：

1. 申请一块更大的新内存（大小 = 旧 capacity × 增长因子）。
2. 将所有已有元素 move（若元素类型有 `noexcept` 移动构造则 move，否则 copy）到新内存。
3. 析构旧内存中的元素，释放旧内存块。
4. 更新内部的 `data` / `size` / `capacity` 指针。

整个过程是强异常安全的（见 `std::move_if_noexcept`）。

### 为什么用倍增而非固定增量？

设有 n 次连续 `push_back`，初始 capacity = 1：

- **固定增量 k**：第 1 次扩容拷贝 k 个，第 2 次拷贝 2k 个……第 n/k 次拷贝 n 个。总拷贝次数 ≈ 1 + 2 + … + n/k = O(n²/k) = **O(n²)**。即使 k 很大，n 充分大后仍是二次代价，每次 push_back 的均摊代价是 O(n)。
- **倍增因子 r > 1**：第 i 次扩容的 capacity = r^i，拷贝 r^i 个元素。总拷贝 = r¹ + r² + … + r^(log_r n) = (r^(log_r n+1) − r)/(r−1) < n·r/(r−1)，是 **O(n)**。每次 push_back 的均摊代价是 **O(1)**。

这就是"几何增长保证均摊 O(1) push_back"的核心证明。

### 2 倍 vs 1.5 倍

- **GCC libstdc++ 用 2 倍**：推导最简洁，均摊 push_back ≤ 2 次拷贝，但每次多占约 1× 的额外内存（最坏浪费 50%）。
- **MSVC STL 用 1.5 倍**：内存浪费降至约 33%。更重要的是：1.5 倍策略满足"新 capacity ≤ 历次释放内存总和"，理论上允许分配器重用旧地址空间（2 倍则永远无法重用）。实际上现代分配器很少利用此特性，但这是设计依据。

两者均摊复杂度均为 O(1)，差别是空间/时间的微小权衡。

### 副作用：迭代器失效

扩容后，所有指向该 vector 元素的迭代器、指针、引用全部失效（因为底层内存地址变了）。这是 vector 最常见的 bug 来源之一，面试时务必提及。

### 实践建议

若预先知道元素数量，调用 `reserve(n)` 一次性分配，避免多次扩容和拷贝。
