关于不同类型容器迭代器失效规则，下列说法正确的是？

```cpp
std::vector<int> v = {1,2,3,4,5};
v.push_back(6);  // ① 可能失效

std::deque<int> d = {1,2,3,4,5};
d.push_back(6);  // ② 可能失效

std::map<int,int> m = {{1,1},{2,2},{3,3}};
m[4] = 4;        // ③ 可能失效
```

A. 三者都会使所有迭代器失效
B. 三者都不会使任何迭代器失效
C. ①② 使所有迭代器失效，③ 不失效
D. ① 若容量不足则使所有迭代器（及引用）失效；② `deque` 在两端 `push` 时仅当插入点在首尾元素之间（`deque` 被分割）的极小概率下使所有迭代器失效，但引用永不失效；③ `map` 插入不使任何现有迭代器失效（只影响新元素的迭代器是否可用）

## Explanation

容器迭代器失效规则是 C++ STL 的重要知识点：

- **vector**：`push_back` 若 `size() == capacity()`，需要重分配——所有指向元素的迭代器、指针、引用全失效；若未重分配，仅 `end()` 迭代器失效。
- **deque**：标准规定（C++03 起）`deque::push_back` 和 `push_front` 会使**所有迭代器失效**（实现可能维护一个指针指向中间块，添加新块时需要调整），但**引用不失效**（元素在块内位置不变）。这一规则的例外是 C++11 起"标准放宽为仅伪失效？" — 事实是不同实现不同，但按标准：`push_back/push_front` 使所有迭代器失效，引用不失效。中间插入会使迭代器和引用都失效。
- **map（关联容器）**：插入不影响已有元素的迭代器有效性——它们继续指向原有元素。
