解释**并发（Concurrency）** 与**并行（Parallelism）** 的本质区别，并举例说明。

**rubric (3 分)：**
- [  ] 核心定义：并发是逻辑上的"同时"（宏观交错执行），并行是物理上的"同时"（多核同时执行）（1 分）
- [  ] 能清楚说明英文术语区别（Concurrency ≠ Parallelism）（1 分）
- [  ] 给出好例子区分两者（1 分）

**期望答案：**

| 概念 | 英文 | 定义 | 本质 |
|------|------|------|------|
| **并发** | Concurrency | 程序结构：多个任务在**同一时间区间内**交替执行 | 逻辑上的"同时"（single core 也能做） |
| **并行** | Parallelism | 程序执行：多个任务在**同一时刻**同时执行 | 物理上的"同时"（需要多核） |

**Rob Pike 经典三段论**（Go 语言之父）：
- **并发是可以同时处理很多事情**（结构层面）
- **并行是可以同时执行很多事情**（执行层面）
- 不是一回事：**并发是结构，并行是执行**

**经典例子：**

**例 1：咖啡机 + 泡面**
- 一个人：先烧水 → 泡面（等待时啥也不干）→ 再泡咖啡——**串行**
- 一个人：烧水 → 水开前就取好面/杯 → 泡面（等待时泡咖啡）→ 更短——**并发**（时间片交替）
- 两个人：一个人泡面一个人泡咖啡——**并行**（物理同时）

**例 2：Web 服务器**
```cpp
// 并发结构：用 EvenLoop + 回调，单线程可处理万级连接
// 每个请求都在同一个线程中分时间片处理
// 这是"并发"而不是"并行"

struct ConcurrencyExample {
    // 单线程事件循环（IO 多路复用）
    // 多个 TCP 连接 → 交替处理 → 逻辑上"同时"服务
    // 但任意时刻只处理一个连接的事件 → 这是并发不是并行
};

// 并行：多个工作线程同时处理不同的任务
struct ParallelismExample {
    // 4 核 CPU 开 4 个工作线程
    // 每个线程处理一个大计算任务
    // 同一时刻 4 个 CPU 核心都在跑 → 这是并行
};
```

**C++ 并发设施的对应：**

| 概念 | 对应 C++ 抽象 |
|------|---------------|
| 并发（结构） | `std::thread`、`std::async`、coroutines、event loop |
| 并行（执行） | `std::execution::par`、SIMD、GPU、MPI |
| 并发 + 并行 | 多线程 + 多核执行（最常见的现代用法） |

**并发 ≠ 并行（重要）**：
- 并发是**程序结构设计**（分解任务，交替执行），单核 CPU 完全可以实现并发
- 并行是**硬件执行状态**（真正同时干多个活），需要多核

但通常现代多核场景**并发任务自然有更多机会变成并行**。

**来源：** 百度 C++ 面试（参考：Rob Pike Concurrency Is Not Parallelism（talk）、《C++ Concurrency in Action》第 1 章）

## Explanation

本题评分重点是区分并发和并行：并发是任务在同一时间段内交替推进的程序结构，单核也能实现；并行是多个任务在同一时刻真正运行，通常依赖多核。好的例子应能说明事件循环处理多个连接属于并发，而多个 CPU 核同时跑计算任务属于并行。C++ 的 thread、async 可表达并发，是否并行取决于调度和硬件。常见误区是把“开了多个线程”直接等同于“并行执行”。
