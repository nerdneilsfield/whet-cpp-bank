# `std::map` 的底层数据结构是什么？红黑树的特性？

## 问题

`std::map` 的底层用什么数据结构实现？请描述红黑树的核心性质，以及 `map` 的查找、插入、删除时间复杂度。

## 参考答案

### 底层：红黑树

`std::map`（及 `std::set`、`std::multimap`、`std::multiset`）的底层是**红黑树**（Red-Black Tree），一种自平衡二叉搜索树。GCC libstdc++ 中对应 `_Rb_tree`，MSVC STL 中对应类似实现，均以节点指针三叉链（parent、left、right）+ 颜色位存储。

### 红黑树的 5 条性质

1. **节点染色**：每个节点是红色或黑色。
2. **根为黑**：根节点是黑色。
3. **叶（NIL）为黑**：所有叶节点（空节点/哨兵）是黑色。
4. **红节点的子节点必须为黑**：不存在两个连续的红节点（即红节点的父子链上没有连续红色）。
5. **黑高相等**：从任意节点到其所有叶子路径上，经过的黑色节点数目相同（称为该节点的"黑高"）。

这 5 条性质共同保证：**树高 h ≤ 2·log₂(n+1)**，即树高是 O(log n) 量级。最坏情况（左右子树黑高相同，但一侧全红一侧全黑）树高也不超过 2 倍完全平衡树高度。

### 时间复杂度

| 操作 | 平均 | 最坏 |
|------|------|------|
| 查找 | O(log n) | O(log n) |
| 插入 | O(log n) | O(log n) |
| 删除 | O(log n) | O(log n) |
| 迭代（全序） | O(n) | O(n) |

插入/删除后需要通过**旋转（rotation）**和**重新着色（recoloring）**来恢复红黑树性质，旋转次数最多为 O(log n)，实践中极少超过 2~3 次。

### 有序性

红黑树是 BST，**中序遍历**即得到按键升序排列的序列。这是 `std::map` 与 `std::unordered_map` 的根本区别：`map` 天然支持有序迭代、`lower_bound` / `upper_bound` 范围查询，代价是每次操作 O(log n) 而非平均 O(1)。

### 内存开销

每个节点存储：key、value、parent 指针、left 指针、right 指针、颜色（通常 1 bit，压入指针低位或单独字节）。指针密集，缓存局部性差，这是 `map` 相比 `unordered_map` 的主要性能劣势（即使复杂度相同，实际吞吐差 3~5 倍）。

### 与 AVL 树对比

AVL 树平衡条件更严（左右子树高差 ≤ 1），树高更低，查找略快；但插入/删除旋转更频繁。红黑树在写多读少场景下旋转次数少，综合性能更优，故被 STL 采用。
