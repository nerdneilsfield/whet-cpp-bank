下列代码返回局部变量地址，编译器可能如何处理，程序行为是什么？

```cpp
#include <cstdio>

int* danger() {
    int local = 42;
    return &local;   // 返回局部变量地址
}

int main() {
    int* p = danger();
    printf("%d\n", *p);   // (A)

    int another = 100;
    printf("%d\n", *p);   // (B)
}
```

A. (A) 输出 42，(B) 输出 42，栈内存未被清零
B. (A) 输出 42，(B) 输出 100，因为 `another` 复用了 `local` 的栈槽
C. 两次都输出 0，操作系统清零了释放的栈帧
D. (A) 和 (B) 均为 UB，编译器可能两次输出不同值、优化掉某次读取、或程序崩溃

---

**解析：**

`danger()` 返回后，`local` 的生命周期**已结束**，其栈内存被"释放"回栈帧池。通过 `p` 访问该内存是 **UB**，不保证任何行为。

**编译器可能做的事（均合法）**：
1. **什么都不优化**：栈内存未被覆盖，(A) 读到 42，(B) 可能读到 100（`another` 复用同一槽）——这是常见"运气好"场景，会掩盖 bug。
2. **删除读取**：编译器检测到指针指向已失效对象，将 `*p` 替换为 `undef`（LLVM IR），输出垃圾值。
3. **折叠为常量**：在某些分析下直接输出 42 或 0（常量折叠 + UB 假设）。
4. **信号/崩溃**：若栈增长覆盖了该地址（递归、信号处理），读取损坏数据。

**现代编译器警告**：GCC/Clang 均会对 `return &local` 发出 `-Wreturn-local-addr` 警告，但不报错。

**关键点**：局部变量地址在函数返回后**立即无效**，编译器的"重用栈帧"优化使两次读取的值甚至可以不一致——(A) 和 (B) 的结果彼此独立地不可预测。

## 解析

正确答案是 D，即 (A) 和 (B) 均为 UB，编译器可能两次输出不同值、优化掉某次读取、或程序崩溃。它符合题目代码/概念对应的 C++ 语言规则或标准库语义，而 A、B、C 通常来自下标、类型、生命周期、复杂度或平台保证的混淆。未定义行为题的关键是区分“标准无保证”和“某次运行看起来正常”；一旦触发 UB，编译器可基于其不会发生来优化。 做这类题时应先判断标准层面的语义，再考虑题目是否给出了特定平台假设。
