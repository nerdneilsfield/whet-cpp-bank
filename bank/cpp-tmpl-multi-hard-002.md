关于模板的两阶段名字查找（two-phase name lookup），以下说法正确的是哪些？

```cpp
template<typename T>
struct Derived : T {
    void f() {
        g();          // (1)
        this->g();    // (2)
        h(x);         // (3) x 是依赖名
    }
};
```

A. 第一阶段（模板定义点）只查找非依赖名（non-dependent names），依赖名推迟到第二阶段（实例化点）查找。
B. (1) 中的 `g()` 在第一阶段按非依赖名查找，不会在基类 `T` 中找到，因此即便 `T` 提供 `g`，调用也通常报错。
C. (3) 中依赖名 `h(x)` 在第二阶段只做普通查找，不会进行 ADL（实参依赖查找）。
D. 用 `this->g()` 或 `T::g()` 显式表明 `g` 是依赖名，可推迟到第二阶段在基类范围内查找。

---

**解析：**

A 正确：标准规定两阶段查找，非依赖名在模板定义时即解析，依赖名延迟到实例化点再解析，这是模板查找规则的核心。
B 正确：在第一阶段，`g()` 不依赖模板参数，编译器不会查看尚未确定的基类 `T`；GCC 严格遵守此规则会报错（MSVC 默认放宽），这正是 CRTP/继承模板时常见坑点。
C 错误：依赖名调用既会做普通查找也会做 ADL，二者结果合并；ADL 正是依赖名的重要部分，禁用 ADL 的说法是错的。
D 正确：通过 `this->` 或限定 `T::` 让名字变成依赖名，从而推迟到第二阶段在已知的基类作用域中查找，这是修复 B 中错误的标准手法。
